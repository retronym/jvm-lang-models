# Phase 29 — `Hier`, `Flat`, `Erasure` and `ImplicitScope` on the shared Scala layer

## Problem

Four `Zinc/` files each define their own toy Scala: class and type enums, a parent walk, a type-argument substitution standing in for `asSeenFrom`, and a query type for the walk. `HierShared` and `FlatShared` embed two of them into `ScalaTypes` and check agreement on bounded spaces, which found real gaps (Hier's depth-first walk on diamonds; two `Members` gaps from `Flat`). But agreement on a space is evidence, not sharing: the next edit to either side can drift, and the Zinc bridge instances, Track B4 (`Links`) and MiMa still do not reason about one Scala semantics. As the shared layer grows (membership, lowering, erasure), every toy is one more copy to keep in step.

Goal: each of the four files *uses* the shared walk, `asSeenFrom`, and (where relevant) refchecks and erasure, so that its theorems are about the same semantics `Scala.Lower` and `Scala.Members` compute. The toys survive only as front ends: small enumerable syntaxes that build [`Scala.Decl`](../../scala-types/ScalaTypes/Syntax.lean#L109)s, so the exhaustive spaces stay enumerable.

## The crux: query granularity

The shared layer reads other definitions through one coarse query, `Scala.Q.decl n isObj`, answered with the whole `Decl`. That is what lowering needs (it reads everything), and it is what Track B4's `searched` bridge keys on.

Hier's designs differ exactly in how finely they key the walk. `D` records `(c, name n)` for "does `c` declare `n`" and `(c, parents)` for `c`'s header; `W` and `Mk` differ in where the walk runs. If Hier's walk asked `Q.decl`, `D`'s only sound key would be the whole declaration, and the precision ladder collapses. Concretely, scenario 1 (`A.m : Int → String`): `Z` selects `B.g`, its walk reads `A`, and with a whole-decl key `Z` recompiles; today `D` recompiles `[X, Y]` only. Flat's header rule and Erasure's per-name witnesses have the same shape.

So the walk must be expressible over *fine* queries, and the coarse form must be the same code, not a second copy.

## Key decisions

1. **Fine queries in the shared layer.** [`Scala.Q`](../../scala-types/ScalaTypes/Resolve.lean#L41) gains `header n` (type-parameter count, kind, parents, the facts `lin` reads) and `member n m` (the definition's own non-`fieldOnly` member named `m`). `decl` stays for consumers that read everything (`Lower`, `Members`, `Links`). [`Program.envIn`](../../scala-types/ScalaTypes/Resolve.lean#L61) answers all three from the same `Decl`, so a fine answer is by construction a projection of the coarse one.

2. **One walk, generic in how it reads.** `lin` and first-member lookup are written once, parametric in a reader (`header`, `member` as `M` actions). The coarse instance reads through `need` and is today's `lin`/`hits` (same results; the trace is the same set of `decl` queries); the fine instance asks `header`/`member`. Written by structural recursion rather than `for … in`, so trace lemmas are provable. One theorem in `ScalaTypes`: under `Program.env p`, the fine and coarse walks give the same result for every program. That replaces `HierShared`'s exhaustive agreement check for the parts that become shared code.

3. **Trace lemmas once.** "The walk asks only `header` and `member` queries" and its congruence corollary (two environments agreeing on those answers give the same walk) are proved in `ScalaTypes`. `HierSound`'s [`trace_linT`](../Zinc/Features/Erasure.lean#L687)/[`trace_firstDecl`](../Zinc/Bridges/HierSound.lean#L55)/[`trace_mergeWith`](../Zinc/Bridges/HierSound.lean#L25)/[`resolveFrom_congr`](../Zinc/Bridges/HierSound.lean#L144) become uses of them, and Flat and Erasure reuse them.

4. **Query translation in `query`.** A generic fold of a task through a query interpretation, `Task.interp : ((q : Q) → Task Q' A' (A q)) → Task Q A α → Task Q' A' α`, with `run`/`trace` lemmas. Each Zinc file maps shared queries into its framework shape `(Cls × Q)` with it (a `Cls`-less name is answered `none` without a query). [`Links.ZincBridge.tr`](../../links/Links/ZincBridge.lean#L67)/`back`/`fq` become an instance.

5. **Toys as front ends.** `Cls`, `Name` and a small `Ty` stay, as the syntax the scenarios and spaces are written in; `toScala` (today in `HierShared`) becomes the front end, and interfaces store [`Scala.Decl`](../../scala-types/ScalaTypes/Syntax.lean#L109). `Hier.Ty.subst`, `mergeWith`, `linT`, `firstDecl` are deleted. Materialised members (`W`) store `Option Scala.Ty`.

6. **Results kept, or the change explained.** Every `D`/`W`/`Mk` obligation theorem and every scenario `Report` should be unchanged. If a report moves (for instance because the shared lookup reads a different set of classes than Hier's early-stopping `firstDecl`), that is a finding about Hier, written down here, not a reason to keep a private walk.

Rejected: keeping the coarse query and keying `D` on whole declarations (loses the precision results above); keeping per-file walks plus agreement checks (today's state: coherence only on the space checked).

## Open questions

- **ImplicitScope.** Extend `ScalaTypes` with implicit definitions and a companion-based implicit-scope search (a real, calibratable piece of Scala semantics), or port only the base-class walk and leave the search local, listed as a gap? The first is more work but is the same argument as for the other three.
- **Early stop.** Hier's lookup stops at the first declaring class; scalac's `findMember` reads every base class. For keys, early stop gives the smaller sound trace. Plan: the shared fine lookup early-stops, with `firstHit = (hits l n).head?` proved, so `Members` (which needs all hits) and Hier share `memberOf`.

## Step 3: `Hier`, the template

What the port of a toy file looks like:

- **The toy's syntax stays as a front end.** `Cls`, `Name`, `Ty`, `Decl`, `Src` are unchanged, so the scenarios and `HierShared.space` are written as before; [`Src.lower`](../Zinc/Bridges/Hier.lean#L101) gives the shared syntax ([`USrc`](../Zinc/Bridges/Hier.lean#L96), a [`Scala.Decl`](../../scala-types/ScalaTypes/Syntax.lean#L109) and the selections), and interfaces hold the [`Scala.Decl`](../../scala-types/ScalaTypes/Syntax.lean#L109).
- **The file's queries are the shared ones, addressed to a unit.** [`Hier.Q`](../Zinc/Bridges/Hier.lean#L120) is `header`, `member m` (the shared queries, asked of the class they name), plus what is the file's own: `members n` (`W`'s materialised members) and the `select n` marker. `toQ` maps [`Scala.Q`](../../scala-types/ScalaTypes/Resolve.lean#L41) into them; [`Task.interp`](../../query/Query/Interp.lean#L20) runs [`Scala.lookupH`](../../scala-types/ScalaTypes/Resolve.lean#L216) through it. `toQFrom d` answers a class's own queries from its source, which is how `W` materialises.
- **The trace lemmas come from the shared layer.** `HierSound`'s walk lemmas are [`Scala.asks_lookupH`](../../scala-types/ScalaTypes/Fine.lean#L502) composed with `toQ` ([`trace_interp_lookupH`](../Zinc/Bridges/HierSound.lean#L63)); the private [`trace_linT`](../Zinc/Features/Erasure.lean#L687), `trace_firstDecl`, `trace_mergeWith` are gone.
- **Keys and hashes follow the queries.** `K.name m` is keyed by the member's name as a string, the same key for the walk's `member m` and a client's `select n`; hashes are a small sum (`H`) instead of a projected interface.
- **The agreement check becomes a theorem.** `HierShared.toy_eq_shared`: for every program, [`Hier.resolve`](../Zinc/Bridges/Hier.lean#L187) is [`Scala.lookup`](../../scala-types/ScalaTypes/Fine.lean#L222) over whole declarations, from [`Scala.lookupH_eq`](../../scala-types/ScalaTypes/Fine.lean#L240) and [`through_agrees`](../Zinc/Bridges/HierShared.lean#L50) (the front end's answers are the program environment's). The sampled `native_decide` and `lake exe exhaustive hiershared` are removed.

Results unchanged: the thirteen scenario reports of `Hier` (`D`, `W` with both policies, `Mk` fresh and stale), and [`D_obligations`](../Zinc/Bridges/HierSound.lean#L166), [`W_obligations`](../Zinc/Bridges/HierSound.lean#L225), [`Mk_obligations`](../Zinc/Bridges/HierSound.lean#L264). `Ty.subst`, `Flat`'s last use of `Hier`'s toy walk, moved into [`Flat.lean`](../Zinc/Bridges/Flat.lean) until step 4.

## Lessons from step 3, for steps 4 to 6

Written after the `Hier` port, 13 October 2026.

- **The agreement check is the theorem's statement.** `HierShared`'s sampled check became [`toy_eq_shared`](../Zinc/Bridges/HierShared.lean#L63) with no new idea: the toy's environment answers the walk's queries as `Program.env` does (`through_agrees`), and the fine walk is the coarse one ([`lookupH_eq`](../../scala-types/ScalaTypes/Fine.lean#L240)). `FlatShared`'s table and `Erasure`'s per-name witnesses should go the same way: keep the space for calibration against the compilers, prove the agreement for every program, and delete the sampled `native_decide`.
- **`Consistent` is the hypothesis to watch.** [`lookupH_eq`](../../scala-types/ScalaTypes/Fine.lean#L240) needs fine answers to be projections of the coarse `decl` answer. [`Program.envIn_consistent`](../../scala-types/ScalaTypes/Resolve.lean#L98) gives it for program environments, which every consumer uses. A bridge that hashes `header` and `member` separately is still inside the theorem, since hashes are keys, not answers; but any port that *answers* a fine query from somewhere other than the declaration (a materialised member table, as `W` does) must prove its environment consistent, as [`mems_unitMat`](../Zinc/Bridges/HierSound.lean#L138) and [`decl_unitMat`](../Zinc/Bridges/HierSound.lean#L135) do for `Hier`.
- **Trace lemmas are `Asks` proofs.** "Asks only header and member queries" composes through [`Task.interp`](../../query/Query/Interp.lean#L20) ([`trace_interp_lookupH`](../Zinc/Bridges/HierSound.lean#L63)) and through the file's own `toQ`. Write the port's trace lemma as `Asks e P` over the shared walk and a `trace_toQ`; do not re-prove walk traces per file.
- **Every new core theorem goes in [`scripts/Axioms.lean`](../../../scripts/Axioms.lean).** Step 3 added four. The lint for `native_decide` and the links lint run in CI; `model_stats.py --check` runs after the build.
- **A moved result is a finding, not a bug.** No scenario report moved in step 3. If one moves in `Flat` (the stored linearization over `header` reads a different set of classes than the toy's walk) or in `Erasure`, record the old and new report and the reason here before adjusting anything.
- **Early stop, decided for `Flat`.** `Hier` early-stops at the first declaring class; `Members` needs every hit. The shared `firstHit` is `(hits l n).head?` and `Flat`'s refchecks prelude needs the full `hits`; both read the same `lin`, so the port keeps one walk and two consumers rather than a flag.
- **`Erasure` needs the header to carry the kind.** Intersection types erase by trait-or-class, so `Q.header` must answer the kind (it does: `Header` has it) and `Lower.erase` is the function to share, extended with `Long` and intersections rather than copied.
- **`ImplicitScope`: port the walk, keep the search local.** The companion-based implicit-scope search is real Scala semantics and worth a calibrated model, but it is a separate feature of the shared layer, not a prerequisite of this phase. Step 6 ports base classes and the trace lemmas, leaves the search in [`ImplicitScope.lean`](../Zinc/Features/ImplicitScope.lean), and lists the shared search as roadmap work.

## Step 4: `Flat`

- **The stored linearization is the shared walk.** `Flat`'s `parents` query became `header`, answered with the lowered declaration's header (`declToScala`, the front end, moved here from `FlatShared`); `linOf` runs [`Scala.linH`](../../scala-types/ScalaTypes/Resolve.lean#L179) through `Task.interp toQ`. The per-parent linearizations that `sameSide` and `mixins` read are the same walk from each parent (`linOfName`), by class. The private `merge`, `parentLins` over `ancestors` and their trace lemmas are gone; [`trace_linOf`](../Zinc/Bridges/Flat.lean#L694) is [`Scala.asks_linH`](../../scala-types/ScalaTypes/Fine.lean#L488) through `toQ`.
- **`Hier.Ty.subst` is deleted.** A member type is seen from a class by the shared `asSeenFrom` (`seen`), over the one-entry world of its owner and the owner's type arguments, as `linMerge` views a parent. That keeps the answer to `member n` a function of the flattened hash (`π (name n)` stays local); `FlatShared` proves it is `asSeenFrom` over the whole linearization. Stored linearizations carry [`Scala.Ty`](../../scala-types/ScalaTypes/Syntax.lean#L20) arguments; selections, forwarders, statics, fields and bridges are [`Scala.Ty`](../../scala-types/ScalaTypes/Syntax.lean#L20), a type parameter erasing to `Object`.
- **`own` is the shared [`Decl.member`](../../scala-types/ScalaTypes/Resolve.lean#L35) as a client sees it**: the first declaration of `n`, unless private. Before, it was the first public one; they differ only when a class declares `n` twice, which no scenario or space does.
- **The agreement checks are theorems.** [`lin_eq_shared`](../Zinc/Bridges/FlatShared.lean#L192): every stored linearization is [`Scala.lin`](../../scala-types/ScalaTypes/Resolve.lean#L176) over the program, for every program (both empty when the walk fails). [`sel_eq_shared`](../Zinc/Bridges/FlatShared.lean#L320): every selection is [`Scala.lookup`](../../scala-types/ScalaTypes/Fine.lean#L222). The shared layer gained [`Scala.asks_linH_of`](../../scala-types/ScalaTypes/Fine.lean#L359) (linearization asks only `header`), since `Flat` answers no `member` query. The sampled `native_decide` is removed; `lake exe exhaustive flatshared` stays for refchecks.
- **Refchecks stay `Flat`'s**, calibrated against `Scala.Members` with the named exclusions (`var`, 2.13's re-check, Scala 3's direct-parent rule) in `FlatShared`; `Members` is not widened. Replacing them with `Members` would key a descendant's checks on whole declarations, which is what the PoC's rule table refines.
- **Finding: a client's selection is not [`Scala.lookup`](../../scala-types/ScalaTypes/Fine.lean#L222) when the receiver declares the name private.** [`Scala.lookup`](../../scala-types/ScalaTypes/Fine.lean#L222) is a class's view of itself and sees its own private member; a client reaches the inherited one (scalac discards the inaccessible alternative). [`sel_eq_shared`](../Zinc/Bridges/FlatShared.lean#L320) takes it as a hypothesis on the receiver; no space has such a selection.
- **Harness.** `lake exe conformance` had not built since step 3 (`all` was ambiguous between [`Hier.Cls.all`](../Zinc/Bridges/Hier.lean#L70) and [`Flat.all`](../Zinc/Bridges/Flat.lean#L883)); fixed, and its `coherent` check moved into [`Flat.coherent`](../Zinc/Bridges/Flat.lean#L937), over the shared `asSeenFrom`.

Results unchanged: `Flat`'s 45 scenario reports and value checks (forwarders, statics, fields and bridges, restated in [`Scala.Ty`](../../scala-types/ScalaTypes/Syntax.lean#L20)), `FlatRules`' minimal counterexamples, [`Fl_obligations`](../Zinc/Bridges/Flat.lean#L759) and [`flat_sound`](../Zinc/Bridges/Flat.lean#L843).

## Step 5: `Erasure`

- **Erasure is [`Scala.erase`](../../scala/Scala/Lower.lean#L44).** `eraseT` runs it over the program lowered to the shared syntax (`envOf`: two type parameters, a value class a `vcls` over its underlying type). Descriptors are its strings ([`JTy`](../Zinc/Features/Erasure.lean#L124) is now `String`); the private descriptor enum and its erasure rules are gone.
- **The shared layer is extended, not copied.** [`Scala.Ty`](../../scala-types/ScalaTypes/Syntax.lean#L20) gains `long` and `inter a b`, an intersection of two definitions. [`Scala.erase`](../../scala/Scala/Lower.lean#L44) erases `Long` (and a value class over it) to `J`, and an intersection to its dominator ([`Scala.eraseInter`](../../scala/Scala/Lower.lean#L33)): the component that is a subclass of the other, else the class over the trait, else the first (scalac's `intersectionDominator` for two components). It reads the components' headers, for their kinds, and their linearizations, not their members.
- **Trace lemmas once, for single-parent languages.** [`Scala.asks_linWith_chain`](../../scala-types/ScalaTypes/Fine.lean#L397) and [`Scala.linWith_chain`](../../scala-types/ScalaTypes/Fine.lean#L438): over a hierarchy whose headers have at most one parent, the walk asks the headers of the parent chain ([`Scala.chainOf`](../../scala-types/ScalaTypes/Fine.lean#L374)) and returns classes of it. `Erasure` relates `chainOf` to its chain ([`chainOf_envOf`](../Zinc/Features/Erasure.lean#L970)); erasing `W with Z` then asks the library trait's header and the headers of `Z`'s chain ([`asks_wz`](../Zinc/Features/Erasure.lean#L1009)), and [`eraseT_congr`](../Zinc/Features/Erasure.lean#L1067) and [`home_abs`](../Zinc/Features/Erasure.lean#L1179) follow from [`Scala.ex_congr`](../../scala-types/ScalaTypes/Fine.lean#L322).
- **Finding: the toy's intersection rule assumed `W` is a parentless trait.** "`Z` if `Z` is a class or extends `W`, else `W`" is scalac's rule only then; the dominator also reads `W`'s kind and base classes, which the key `(Z, cls)` does not cover. `W` is a library trait in this language (no source edits it), so the front end lowers it as `trait W`; were it editable, the erasure of `W with Z` would need `W`'s class-name key too.
- **Two changes no scenario or space observes.** The class-name hash's kind is the lowered kind (trait, value class or class) rather than "is a trait", since [`Scala.erase`](../../scala/Scala/Lower.lean#L44) reads it from the header (a value class's `extends AnyVal` is a parent, which Zinc's class-name hash covers anyway); and `depth` is `Scala.fuel + 1`, so that the pure chain covers every class the shared walk reads (it was 4; no chain in the space or the scenarios is longer than 3).
- **Not ported: `Erasure`'s own walk** (`linT` and `Ty.subst` over two type parameters). Its `parent` query answers parents only, keyed by the inheritance and class-name keys, which do not hash kinds; answering the shared `header` from it would have to invent the kind. Porting it needs the walk's congruence up to kind (the result reads only names and parents), a shared lemma like [`lin_fine`](../../scala-types/ScalaTypes/Fine.lean#L167). Left as remaining work of this phase.

Results unchanged: every scenario report and the per-name witnesses, [`Er_obligations`](../Zinc/Features/Erasure.lean#L1199), [`fresh_obligations`](../Zinc/Features/Erasure.lean#L1314), [`dep_obligations`](../Zinc/Features/Erasure.lean#L1318), [`dep_sound`](../Zinc/Features/Erasure.lean#L1322), [`asf_of_decl`](../Zinc/Features/Erasure.lean#L627); the erasure values of the intersection scenarios are pinned (`LW;`, `LZ;`, `LZ;`).

## Step 6: `ImplicitScope`

- **Base classes are the shared walk.** `chainT` runs [`Scala.linH`](../../scala-types/ScalaTypes/Resolve.lean#L179) through `Task.interp toQ`, where a class's `header` is its `parents` answer (an object's kind is `obj`), and reads the result by class with the object flags. The private parent loop is gone. Its trace, [`trace_chainT`](../Zinc/Features/ImplicitScope.lean#L515), is [`Scala.asks_linWith_chain`](../../scala-types/ScalaTypes/Fine.lean#L397) through `toQ`, with `chainOf_envOf` (the chain through the headers is `chainP`); the base classes it returns are on that chain by [`Scala.linWith_chain`](../../scala-types/ScalaTypes/Fine.lean#L438) ([`mem_chainT`](../Zinc/Features/ImplicitScope.lean#L529)).
- **The pure views read one class beyond the walk.** The walk's fuel is four (`walkFuel`) and `depth` five: the walk asks up to five headers and succeeds on chains of up to four classes, where the loop it replaces truncated at four. A chain longer than four now has no base classes (the walk fails) rather than a cut-off list; no scenario or program of the space has a chain longer than three.
- **The companion search stays local**, as decided: `cscT`, `select` and `bases` are this file's. The shared implicit-scope search is listed in [`docs/roadmap.md`](../../../docs/roadmap.md).

Results unchanged: every scenario, [`is_obligations`](../Zinc/Features/ImplicitScope.lean#L675), [`is_sound`](../Zinc/Features/ImplicitScope.lean#L731), [`stored_eq_recomputed`](../Zinc/Features/ImplicitScope.lean#L835) (now for heights below five) and [`consistent_of_upToDate`](../Zinc/Features/ImplicitScope.lean#L850).

## Calibration after steps 4 to 6

The compiled checks, run before (at `1dcabf2`) and after the ports, give identical output: `lake exe exhaustive` over the first 20,000 of `FlatRules`' bases (540,000 edits, every rule set), `exhaustive v` (69,120 edits), `exhaustive flatshared` for 2.12, 2.13 and 3 (linearization and selections agree on all 216,000 programs; refchecks 171,392 / 103,824 / 184,064 of the 192,000 without a `var`), `exhaustive erasure` (the 189,888-pair table above, unchanged), `exhaustive implicit`, and the conformance dumps (`lake exe conformance`, `conformance v`) byte for byte.
