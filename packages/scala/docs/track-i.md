# Track I — Interruptibility: a presentation compiler over lazy facts

21 October 2026. Builds on [Track L](track-l.md): the symbol table as a lazy evaluator.

## Summary for a busy reader

A presentation compiler answers requests while it is in the middle of type checking. "Interrupt" covers two different things: **abort** (the work in progress is thrown away and restarted: scalac's `FreshRunReq` and `CancelException`, IntelliJ's `ProcessCanceledException`) and **nested servicing** (the request runs *inside* the type check in progress, on the same thread, against the same symbol table: scalac's `signalDone` → `pollForWork`). The property wanted is weaker than thread safety, since nothing runs at the same time, but it is not implied by it: a lock lets a nested request straight in (reentrant) or deadlocks (not), so locking does not help. It is the discipline of async-signal safety: every invariant over mutable state has to hold at every safepoint. The closest prior art is asynchronous exceptions in a lazy language [Marlow et al. 2001]: an interrupt may land inside a thunk under evaluation, and the runtime's answer, freezing the partial evaluation so that the next demand resumes it, is abort safety over lazy facts; the black hole a thunk under evaluation becomes [Peyton Jones 1992; Harris et al. 2005] is scalac's `LOCKED` and dotc's `Touched`.

Over the lazy facts of Track L (the `Task` model of [Mokhov et al. 2018]) the property is free. Every intermediate store of `force` agrees with the semantics ([`force_ok`](../../query/Query/Lazy.lean#L111): `Agree ρ` and `Ext` hold at each step), so a prefix of a forcing leaves a store that is right as far as it goes; abandoning it and restarting gives the same answers, and a nested request serviced with an empty stack is a reordering of demands ([`forceAll_ok`](../../query/Query/Lazy.lean#L160)). The bugs are where a compiler leaves that discipline. [scala/scala#11328](https://github.com/scala/scala/pull/11328) (open, the fix for the flaky presentation tests of [scala-dev#840](https://github.com/scala/scala-dev/issues/840) and [#915](https://github.com/scala/scala-dev/issues/915)) is five of them, one of each kind of non-fact state:

| [scala/scala#11328](https://github.com/scala/scala/pull/11328) commit | the state that is not a fact | the invariant it broke at a safepoint |
|---|---|---|
| `uninterruptible(addSyntheticMethods)` | a class's member set, grown in a burst with safepoints between | `addSyntheticMethods` is all-or-nothing ("already has … not adding"): a nested retype saw part of the burst and skipped the rest |
| `uninterruptible(addSynthetics)`, `consumeSynthetic` | `unit.synthetics`, a per-run map **consumed** when a tree is added | a nested full type check took the remaining trees; a targeted check consumed them and was abandoned |
| keep the implicit factory | the factory symbol's **identity**, replaced each time the template was typed | the run's implicit cache held the replaced symbol, now "shadowed" |
| suspend a targeted check's warnings | `suppressionsKnown`, a **completeness claim** about the unit's `@nowarn`s | a targeted check that stopped early made the claim |
| `CommentPreservingTypers` | a **derived cache** (`cookedDocComments`) whose source (`DocDef`s) typing destroys | cleared per run, not per source |

Three architectures take three positions on this. **scalac** services requests nested, and pays with a safepoint invariant over all of the above. **dotc under Metals** never interrupts: a request is a fresh `Run` of its file on a shared symbol table, requests wait in a one-thread LIFO queue, a running job is not interrupted (there is no presentation compiler thread, and an interrupt bit is swallowed at the checkpoints), and any exception throws the driver away; it pays with whole-unit recompilation. **IntelliJ's PSI** aborts only: a read action is cancelled at its next `checkCanceled` by a write action, and restarted; everything but the parse is a pure function cached under a modification count, computed by whoever asks first, with a recursion guard that answers `null` on re-entry and forbids caching above the re-entered frame; it pays with the design constraint that read actions write nothing but caches.

[`probes/interrupt`](../probes/interrupt) is the three architectures distilled into one Java program (about 1,100 lines) over a toy language of classes and members without expressions, and a harness that injects one request at every safepoint of the background work and compares the answers with the request arriving after it. Under the scalac kernel with the policy before [scala/scala#11328](https://github.com/scala/scala/pull/11328), the four scenarios modelled on the PR's tests diverge at 8–13 of 14–18 safepoints; with the PR's policy, at none. The dotc and PSI kernels diverge at none, in every scenario, by construction. The toy also predicts two behaviours of scalac *after* the PR, for a request that types the whole unit (`askType(source)`) served inside the background check of that unit ([results.txt](../probes/interrupt/results.txt), `case-class-loaded`): served before the class is typed, the background's final tree, which later `askLoadedTyped`s return, has none of its synthetics; served after, the request's own tree has none. Both are testable with the PR's own `signalDone` hook, and are findings I1 and I2.

## 1. What [scala/scala#11328](https://github.com/scala/scala/pull/11328) is about

scalac's interactive `Global` runs one compiler thread. `backgroundCompile` types the loaded units; the typer calls `signalDone` after every tree it types, and there, if `interruptsEnabled && lockedCount == 0 && !context.bufferErrors`, `checkForMoreWork` services the requests that have arrived, *inside* the type check in progress. A targeted request (`askTypeAt`, `askTypeCompletion`) types the unit until the tree containing the target position is typed and unwinds with `TyperResult`; `askType(source)` types the whole unit nested; `askReload` starts a new run and unwinds the background check with `FreshRunReq`. The three guards cover the facts: no completer is in progress (`lockedCount`), no speculative typing is in flight (`bufferErrors`), and no region has asked to be left alone (`interruptsEnabled`, which the PR makes settable from the typer).

Everything [scala/scala#11328](https://github.com/scala/scala/pull/11328) fixes is state outside the facts, listed in the summary. The PR's two new tests are the shape of the harness below: a `signalDone` override that blocks the compiler thread at the first serviceable safepoint until a completion has been posted, then an `askLoadedTyped` whose tree is compared with the expected one. Jason's review comment asks for the generalisation: a soak test that interrupts with random interleavings. [`Harness.java`](../probes/interrupt/src/pctoy/Harness.java) is that, exhaustively, over the toy.

## 2. Three architectures

### scalac (`src/interactive`)

* Where a request runs: nested, at `signalDone` (`Global.scala:337`), through `pollForWork`.
* Symbol table: one, shared across runs. A new run re-enters a reloaded unit's definitions with `enterExistingSym`, which keeps the symbols and resets their infos to completers, so references from other units stay valid by identity.
* The black hole: `LOCKED`, set in `completeInfo` and reset in its `finally` (`Symbols.scala:1559-1600`), so an abort through a completer leaves the symbol forceable; a cycle gives the asked symbol `ErrorType` for the run.
* Cancellation: `CancelException` and `FreshRunReq` unwind to the run loop; `TyperResult` unwinds a targeted check.

### dotc (`compiler/src/dotty/tools/dotc/interactive`) under Metals (`presentation-compiler`, mtags-shared's `CompilerAccess`)

Read for this track in scala3 at `d168df2a76` and mtags-shared 1.6.9; the survey's details are in the agent report summarised here.

* Where a request runs: `InteractiveDriver.run(uri, source)` makes a fresh `Run` from `myInitCtx` for every request, sharing the `ContextBase` (symbol table, phases) across runs (`InteractiveDriver.scala:81-107`). `CachingDriver` skips the run when the URI is the last compiled and the text unchanged. There is no targeted type check: the whole unit is typed, and completions and hovers are read off the typed tree afterwards.
* Symbol table: shared. A run of a file unlinks the file's symbols from earlier runs when the package symbol is created (`unlinkFromFile`, `SymDenotations.scala:2792`); references to them from other facts are stale denotations, and in `Mode.Interactive` (`Config.ignoreStaleInIDE`) `bringForward` accepts them and resolves by name to the current symbol. A completer created in an older run does not run: the symbol gets `UnspecifiedErrorType` (`Namer.scala:933`). After a run, `cleanup` gives every symbol in the typed tree whose info is still lazy an error type, so no completer captures an old run's context.
* The black hole: `Touched`, set in `completeFrom` (`SymDenotations.scala:150-176`) and **not** reset if the completer throws; `isCompleting` then stays true and the next access is a `CyclicReference`. `LazyAnnotation` leaves `myTree = null` the same way. `BaseData` does use `try/finally`.
* Cancellation: the compiler checks `Thread.interrupted()` only at unit and subphase boundaries (`Run.checkCancellation`, `Phases.monitor`); nothing inside typer, completion or implicit search checks (the separate `Run.isCancelled` flag is the import-suggestion timeout). With `InteractiveDriver`'s callback (`isCancelled() = Thread.interrupted()`, `cancel()` a no-op) a pending interrupt is cleared by the first `Thread.interrupted()` and the checkpoint reports "not cancelled". And Metals never sends one: `Scala3CompilerWrapper.presentationCompilerThread` is `None`, and `CompilerAccess.withInterruptableCompiler` interrupts only when there is a thread. Requests go through `CompilerJobQueue`, a one-thread executor over a LIFO queue; a cancelled token drops a job that has not started (`result.cancel(false)`), a timeout resets the queue and discards the compiler while the old job keeps running on the old driver; `withSharedCompiler` maps `InterruptException` to the default answer and keeps the driver, and any other `Throwable` to `shutdownCurrentCompiler`, so the next request builds a new driver with a new `ContextBase`.

So dotc is interruptible by not being interrupted: a request is an idempotent unit of work at the granularity of a file, and the only recovery is to throw the driver away. The hypothetical kernel `dotc-interrupted` below asks what would happen if an interrupt did land mid-run and the driver were kept, as `withSharedCompiler` does for an `InterruptException`.

### IntelliJ PSI (platform `RecursionManager`, `CachedValuesManager`; the Scala plugin's `caches` package)

* Where a request runs: on its own thread as a read action, concurrently with the daemon's. No request is ever serviced inside another computation.
* Symbol table: none. Declarations are stubs, available from the parse without any computation (level 0 of Track L §3). Everything else (`members`, a member's type, the implicit candidates) is a pure function of the stubs, cached per element under a modification count (`CachedValue`; the plugin's `Cache0`/`CacheN` compare a `modCount` and `compareAndSet` the value, under `ModTracker.anyScalaPsiChange` or a `BlockModificationTracker` for edits inside a body). Identity across edits is a `SmartPsiElementPointer`, which re-resolves.
* The black hole: `RecursionManager.doPreventingRecursion(key, memoize, computation)` returns `null` on re-entry (`RecursionManager.java:95-103`) and marks every frame above the re-entered one, so `StackStamp.mayCacheNow()` is false there and the value is not cached (`CacheInUserData.scala:32`, `Cache0.scala:32`). A result that depended on what was on the stack never reaches the store: the exact cure for Track L's peeking consumer ([`forcePeek`](../../query/Query/Lazy.lean#L249)), whose order-dependent answer scalac memoizes.
* Cancellation: a pending write action makes every read action's next `ProgressManager.checkCanceled()` throw `ProcessCanceledException`; the reader unwinds without publishing (a `CachedValue` is stored only on return) and is restarted (`ReadAction.nonBlocking`).

The difference in one line: scalac buys latency by running other requests inside the current one and pays with a safepoint invariant over all mutable state; PSI buys it by abort-and-restart and pays with the separation of reads from writes and caches that are pure; dotc under Metals buys simplicity by neither interrupting nor nesting, and pays in recomputation.

## 3. The toy

[`probes/interrupt/src/pctoy`](../probes/interrupt/src/pctoy), plain Java 21, `run.sh` compiles and runs it.

**The language** ([`Ast.java`](../probes/interrupt/src/pctoy/Ast.java)): a file is classes, objects and traits with members and no expressions. A member's type is declared (`def m: T`) or inferred from a path (`def m = a.b.c`): the first name is a member of the enclosing class or a top-level object, each further name a member of the type so far, or, failing that, of an implicit class in scope that takes that type. Inference is what forces other facts, so this is enough for cycles (`def a = b; def b = a`), levels (a class's members are entered before any member's type is asked), synthetics with the structure of scalac's (a `case` class gets `copy`, `equals`, `hashCode`, `toString` in a burst and a companion with `apply` and `unapply` through `unit.synthetics`; an `implicit` class gets a factory method), implicit search with a per-run cache and a shadowing check, and warnings with `@nowarn` suppression (`deprecated def`, `nowarn object`).

**The shared symbol table** ([`Global.java`](../probes/interrupt/src/pctoy/Global.java)): symbols with completers, `force` with the black hole, a namer per run, a typer that calls `signalDone` after each member, each synthetic and each class, as well as inside a completer (where `lockedCount > 0` and scalac would not service). `Policy` holds six booleans: the four choices the PR changed (an uninterruptible synthesis burst, synthetics kept for a targeted check with scalac's `SynthesizedMethods` attachment, the factory symbol kept, a targeted check's warnings left suspended), `unlockOnUnwind` (scalac true, dotc false) and `reuseSymbols` (scalac's `enterExistingSym` true, dotc's `unlinkFromFile` false, with stale symbols re-resolved by name).

**Five kernels**, each a `Kernel` ([`Core.java`](../probes/interrupt/src/pctoy/Core.java)) with `reload`, `send(event)` and `drain()`:

| kernel | where a request runs | model of |
|---|---|---|
| `scalac-before`, `scalac-after` ([`Scala2Kernel`](../probes/interrupt/src/pctoy/Scala2Kernel.java)) | nested at `signalDone` when `interruptsEnabled && lockedCount == 0`; a targeted check unwinds with `TyperResult`; an edit is a new run and `FreshRunReq` | scalac before and after [scala/scala#11328](https://github.com/scala/scala/pull/11328)'s four policy changes |
| `dotc-metals` ([`Scala3Kernel`](../probes/interrupt/src/pctoy/Scala3Kernel.java)) | a fresh run of the file per request, whole unit, LIFO queue, never interrupted, `CachingDriver`'s skip, `cleanup` | dotc under Metals |
| `dotc-interrupted` | as above, but the interrupt is delivered once at the next checkpoint of the job it arrived in, the job unwinds, and the driver is kept | the hypothetical `InterruptException => default` path |
| `psi` ([`PsiKernel`](../probes/interrupt/src/pctoy/PsiKernel.java)) | stubs by name; `cached(key)` under a modification count with a recursion guard that answers `null` and taints the frames above; a request is a read action on a fresh guard stack; an edit is a write action that cancels the daemon at its next `checkCanceled` | IntelliJ PSI as the Scala plugin uses it |

**The harness** ([`Harness.java`](../probes/interrupt/src/pctoy/Harness.java)): a scenario is sources and one event, a request (`completion F Decl.member`: the members of the target member's type, implicit views marked `via`; `loadedTyped F`: every declaration's typed body and the problems reported, scalac's `askType(source)`) or an edit followed by a request. The background's safepoints are counted on a fresh kernel; the reference answers come from a fresh kernel with the event sent after the background finishes, followed by a `loadedTyped` of each file; then, for each safepoint `k`, a fresh kernel gets the event injected at `k`, and its answers (the event's, then the final `loadedTyped`s) are compared with the reference. "Work" counts completers run and members typed, so the price of each design shows beside its correctness.

What the table says:

* **The PR's four fixes close the four shapes they target**, and the toy reproduces each with the mechanism the commit messages describe: the partial burst and the all-or-nothing skip, the consumed map, the replaced symbol in the cache, the premature completeness claim. In `implicit-class` the divergent safepoints are 0–6 and 14–16: a completion served while `Before` is typed (the factory replaced after the cache is filled) or after `Use.g` is typed (the cache filled, then the factory replaced by the next retype).
* **A nested full type check is still unsafe after the PR** (`case-class-loaded`, finding I1/I2). Served at a safepoint before the background has typed the case class, the nested check consumes the synthetics and the background's own tree, which it stores last, lacks the companion, `apply`, `unapply` and, by the all-or-nothing skip, `copy`..`toString`; served after, the request's own tree lacks them all. The PR closes only the window inside `addSynthetics`. The mechanism in scalac is `typeCheck(unit)` (`Global.scala:675`): the outer `typer.typed(unit.body)` took the old body as its argument and assigns `unit.body` when it returns, after the nested one; `typed` short-circuits only trees that carry a type, and the old `ClassDef` does not. This is a prediction from the toy, to be checked with a test in the shape of the PR's.
* **dotc under Metals never diverges**, and does no extra work for a request that arrives during the background compile, because the request waits. The reference work equals the mean: the design has no interleavings. Its cost is elsewhere, in a whole-unit run per edit, which the toy's one-file scenarios do not weigh.
* **An interrupt delivered to dotc would be mostly harmless, and the cache keyed on the last file is the hazard.** `dotc-interrupted` recomputes (mean work 26.7 against 17.0) and diverges only in `edit-cross-file`, at the safepoints inside `B`'s initial compile: the abandoned run leaves `CachingDriver`'s "last compiled" at `A`, so the request after the edit answers from `A`'s compilation against the state before `B` existed. The `Touched` leak does not show in these scenarios, because `cleanup` and the fresh run per file leave no cross-file completer to be interrupted; it would need a symbol loader, which has its own `finally`.
* **PSI never diverges and does the least work**: the completion after the background costs nothing, an interleaved one computes only what it needs, and the daemon re-annotates only after a change. The recursion guard gives the true cycle the same error in every interleaving, as scalac's `LOCKED` with `ErrorType` does; the two differ for a *peeking* consumer (Track L §6), which the toy does not yet have. Demand-driven attribute evaluation met the same choice first: a reference attribute grammar evaluator detects a cycle on demand and reports it [Hedin 2000], or, for attributes declared circular, iterates to a fixed point from a bottom value [Magnusson and Hedin 2007]; a peek that answers `absent` is the bottom value without the iteration, which is why L2's two orders can only agree through a fixed point of the name sets (§8).

## 5. The theory, and what the model says

The nested-servicing bugs are all outside `Query.Lazy`'s store, so the formal step was to add what they are over. [`Query/Interrupt.lean`](../../query/Query/Interrupt.lean) (§7) states each item of the theory; the table gives the theorem for each.

| the claim | the theorem |
|---|---|
| **Abort safety is a corollary.** Any prefix of a forcing leaves a store satisfying `Agree ρ` and `Ext`; restarting from it gives the same answers | [`forceA_agree`](../../query/Query/Interrupt.lean#L158) (every intermediate store, with only a fixed point, no ranking), [`abort_restart_ok`](../../query/Query/Interrupt.lean#L208) |
| `unlockOnUnwind`: an aborted frame must leave the stack. scalac's `finally unlock()` satisfies it; dotc's `completeFrom` does not, and an aborted dotc frame is a permanent black hole for the run | [`forceA_unlock_touched`](../../query/Query/Interrupt.lean#L315) (scalac), [`abort_touched`](../../query/Query/Interrupt.lean#L269) and [`touched_stays_cyclic`](../../query/Query/Interrupt.lean#L287) (dotc); the chain [`chain_restart_scalac`](../../query/Query/Interrupt.lean#L362), [`chain_restart_dotc`](../../query/Query/Interrupt.lean#L366) |
| **Nested servicing is a reordering when the stack is empty** | [`nested_empty_stack_reorders`](../../query/Query/Interrupt.lean#L378) |
| With a non-empty stack it can black-hole on a fact the program's rules rank: a re-entry of the frame in progress, a cycle the interleaving makes rather than the program (not Track L's bundling) | [`nested_inside_frame_cycles`](../../query/Query/Interrupt.lean#L415) (ranked by [`nested3_ranked`](../../query/Query/Interrupt.lean#L405)) |
| or, under peek semantics, an order-dependent answer that gets memoized | [`forcePeek_memoizes_order`](../../query/Query/Interrupt.lean#L739); for scalac's implicit search, [`implicitSkip_memoizes_wrong`](../../scala-types/ScalaTypes/Laziness.lean#L268) |
| PSI's taint is the fix: a peeked answer is not stored, so the store still agrees with `ρ` | [`forceT_agree`](../../query/Query/Interrupt.lean#L668) (full taint, any program with a fixed point); under ranked rules nothing peeks `absent` at all, [`forcePeek_ok`](../../query/Query/Interrupt.lean#L467) |
| IntelliJ's rule caches the re-entered frame, and that frame's answer depends on the demand order | [`psi_root_order_dependent`](../../query/Query/Interrupt.lean#L748) (finding I4); [`implicitSkip_psi_ambiguous`](../../scala-types/ScalaTypes/Laziness.lean#L284), where the root happens not to depend on it |
| A pushed fact read in the middle of its burst is `Query.Freeze` without the freeze; "uninterruptible" is the burst having no safepoint | [`burst_allOrNothing_whole_iff`](../../query/Query/Interrupt.lean#L797) (whole only at safepoints 0 and 4), [`burst_perElement_whole`](../../query/Query/Interrupt.lean#L802) |
| A consumed map is a linear resource: each synthetic is added once to one tree, and the tree kept may be the other one | [`consuming_add_one_owner`](../../query/Query/Interrupt.lean#L848), [`idempotent_add_complete`](../../query/Query/Interrupt.lean#L840) (over all 20 interleavings of two checks) |
| An identity cache is sound only if the symbol it names is stable within the run | [`keep_cache_sound`](../../query/Query/Interrupt.lean#L884), [`replace_cache_unsound`](../../query/Query/Interrupt.lean#L912) |
| A completeness claim (`suppressionsKnown`) is a freeze made by a computation that did not finish | the burst shape again, with the `@nowarn`s as the pushes; not modelled separately |

## 6. Beyond this phase: targeting and incrementality

Two properties sit next to interruptibility and are out of scope here, because they are about trees, which the model does not yet have.

**Targeting** is typing only what a request needs. scalac has it in the typer: a targeted check types the unit's statements until the tree containing `targetPos` is typed and unwinds with `TyperResult`, so a completion in the last method of a long file still types every method before it, and the trees it typed are kept for the full check (the attachments of [scala/scala#11328](https://github.com/scala/scala/pull/11328) exist because the two checks share them). dotc has none: a request types the whole unit and reads the answer off the tree (`CachingDriver` only avoids repeating it). PSI is targeted by construction: there is no "type the unit", only facts demanded by name, and a completion asks for exactly the member types on its path. Over facts, targeting is just demand; over trees, it is the question of which subtrees a request may leave untyped, and what a later request may assume about them. The toy's `Completion` under the scalac kernel is a targeted check in that sense, and the `targeted-consumes-synthetics` scenario is the price: a targeted check leaves state the full check has to find.

**Incrementality** is reusing typed results across edits [Reps et al. 1983; Acar et al. 2002; Hammer et al. 2014]. scalac and dotc under Metals both start a run and retype the edited unit whole; their incrementality is at the granularity of a file, and across files by symbol identity (scalac) or by name (dotc). PSI invalidates by modification trackers: an edit inside a method body bumps only that body's tracker (the Scala plugin's `BlockModificationTracker`), so member signatures and everything derived from them survive the edit. In the toy every edit is structural and bumps everything, so the work column cannot show this. A model of it needs trees with positions, an edit as a tree replacement, and a dependency relation from facts to the subtrees they read, which is the fact-level counterpart of Zinc's name hashing; the question is then which facts an edit inside a body can invalidate, and the answer is the one `BlockModificationTracker` encodes.

Both belong with the tree model: a request's target is a position in a tree, and an edit is a change to one [Wagner and Graham 1998; Lippert 2012]. Identity across edits, which the dotc kernel resolves by name and scalac by reuse, is the problem [Hammer et al. 2015] solve with explicit names.

## 7. The model

[`Query/Interrupt.lean`](../../query/Query/Interrupt.lean), 21 October 2026, over [`Query/Lazy.lean`](../../query/Query/Lazy.lean) and [`Query/Freeze.lean`](../../query/Query/Freeze.lean); no Mathlib, no `native_decide`. The witnesses with scalac's implicit search are in [`ScalaTypes/Laziness.lean`](../../scala-types/ScalaTypes/Laziness.lean).

**Abort.** `forceA` is `force` with two changes. A *budget* of safepoints: before each fact a rule asks (the toy's `signalDone` after each member), the budget ticks down, and when it is spent the forcing returns `abort` with the store so far; `none` schedules no abort. And a *touched* set in the state instead of the stack as the black hole: entering a completer marks its fact, leaving with a value stores the value and unmarks it, leaving any other way (a black hole below, out of fuel, the abort) unmarks it only under scalac's discipline (`unlock`, `completeInfo`'s `finally`); dotc's `Touched` stays. [`forceA_agree`](../../query/Query/Interrupt.lean#L158) is the statement that interruptibility is free over the facts, and it needs less than [`force_ok`](../../query/Query/Lazy.lean#L111): a fixed point of the rules suffices, with no ranking, for every intermediate store to agree with it and keep every finished fact, under any budget, fuel, stack and discipline. The argument is the one inside [`force_ok`](../../query/Query/Lazy.lean#L111)'s induction, read as an invariant: a stored value is a rule's output over answers that were themselves stored or returned, and both agree with `ρ`. [`abort_restart_ok`](../../query/Query/Interrupt.lean#L208) is then [`force_ok`](../../query/Query/Lazy.lean#L111) from the aborted store. The disciplines differ after the abort: [`forceA_unlock_touched`](../../query/Query/Interrupt.lean#L315), with `unlock` the touched set is left as found, however the forcing ends, so the restart finds no black hole; [`abort_touched`](../../query/Query/Interrupt.lean#L269) and [`touched_stays_cyclic`](../../query/Query/Interrupt.lean#L287), without it the aborted fact (and every frame below it) stays touched, and the next forcing of it is a cyclic reference for the rest of the run. The chain `a → b → c → d` with the abort inside `c` shows both ([`chain_restart_scalac`](../../query/Query/Interrupt.lean#L362), [`chain_restart_dotc`](../../query/Query/Interrupt.lean#L366)). Under Metals this never happens because nothing interrupts dotc; it is what the hypothetical `dotc-interrupted` kernel would pay, beyond the recomputation §4 measured.

**Nested servicing.** [`nested_empty_stack_reorders`](../../query/Query/Interrupt.lean#L378): the background has forced `before` and will force `after`, the request `req` is serviced in between with nothing in progress; with a ranked fixed point every answer is the value under `ρ`, the same as with the request after the background. It is [`forceAll_ok`](../../query/Query/Lazy.lean#L160) twice, which is the point: a request at a safepoint with an empty stack adds nothing to the theory. [`nested_inside_frame_cycles`](../../query/Query/Interrupt.lean#L415): `a` asks `b`, `c` asks `a`, ranked; a request for `c` serviced inside `a`'s completer, after `b` returned, finds `a` in progress and black-holes, a cycle that no order of top-level demands produces. That is why scalac's `pollForWork` requires `lockedCount == 0`.

**Peeking with taint.** A result carries a *taint*: `none`, or `some m`, the stack position above which it may not be cached. A peek that finds its fact in progress at position `p` taints `some (p + 1)`, the frames strictly above it, which is `RecursionManager.prohibitResultCaching`; in full mode it taints `some 0`. A frame stores its value only if the taint lets it ([`Taint.caches`](../../query/Query/Interrupt.lean#L532)). Two results first. [`forcePeek_ok`](../../query/Query/Interrupt.lean#L467): under *ranked* rules (with each peek read as a force), `forcePeek` never sees an `absent`: a peek at a fact in progress would put that fact in its own transitive trace, against the ranking. So taint is idle on well-founded programs, and the order dependence of a peeking consumer is confined to programs whose definitions are cyclic once the peek is read as a force, which is where [`forceAll_ok`](../../query/Query/Lazy.lean#L160) was already silent. [`forceT_agree`](../../query/Query/Interrupt.lean#L668): for any program with a *fixed point*, ranked or not, full taint keeps every stored value equal to the fixed point's, since nothing computed from an `absent` is ever stored; the price is that a fact on a cycle through a peek is recomputed on every demand. Then the witnesses, on two facts that peek at each other (`a = a(b)`, `b = b(a)`, no fixed point): `forcePeek` stores `b = b(absent)` or `b = b(a(absent))` by demand order ([`forcePeek_memoizes_order`](../../query/Query/Interrupt.lean#L739)); IntelliJ's rule stores the *root* of the cycle, whose value was computed with `absent` for its own re-entry, and the root is whichever fact was demanded first ([`psi_root_order_dependent`](../../query/Query/Interrupt.lean#L748), finding I4); full taint stores nothing ([`fullTaint_stores_nothing`](../../query/Query/Interrupt.lean#L755)). On scalac's implicit-search program of Track L §6 (`y` forces `z`, `z` peeks `y`), which does have a fixed point ([`implicitRules_fix`](../../scala-types/ScalaTypes/Laziness.lean#L261): `y : Int`, `z` ambiguous, the separate compilation's answer), `forcePeek` memoizes `z = x` ([`implicitSkip_memoizes_wrong`](../../scala-types/ScalaTypes/Laziness.lean#L268)), full taint rejects the program in every order as dotc does ([`implicitSkip_taint_rejects`](../../scala-types/ScalaTypes/Laziness.lean#L275)), and IntelliJ's rule caches `y`, whose value does not depend on `z`'s, and then answers `z` as the separate compilation does ([`implicitSkip_psi_ambiguous`](../../scala-types/ScalaTypes/Laziness.lean#L284)).

**The state that is not a fact.** Three models the size of the mechanism. (a) A burst: `addSyntheticMethods` enters four members with a safepoint after each; a request at safepoint `k` reads the set so far ([`Query.Freeze.unguarded`](../../query/Query/Freeze.lean#L34) with the read at `k`) and adds what its policy says; its view is what it read plus what it added. All-or-nothing ("already has … not adding") is whole only at `k = 0` and `k = 4` ([`burst_allOrNothing_whole_iff`](../../query/Query/Interrupt.lean#L797)): `uninterruptible` is the removal of safepoints 1 to 3. Per element (`idempotentSynthetics`) is whole at every `k` ([`burst_perElement_whole`](../../query/Query/Interrupt.lean#L802)). (b) A consumed map: two checks of one template, interleaved at safepoints in all 20 ways, each walking `unit.synthetics`; a consuming add gives each item to exactly one tree ([`consuming_add_one_owner`](../../query/Query/Interrupt.lean#L848)), and the kept tree may be the other one (finding I1 is this with the background's tree kept); an idempotent add gives both trees every item ([`idempotent_add_complete`](../../query/Query/Interrupt.lean#L840)). (c) An identity cache: a lookup fills the cache with the current symbol and later answers whether the cached symbol is still the current one (scalac's shadowing check); with the symbol kept across retypes every lookup finds it, under every schedule ([`keep_cache_sound`](../../query/Query/Interrupt.lean#L884)); with it replaced, fill, retype, lookup finds it shadowed ([`replace_cache_unsound`](../../query/Query/Interrupt.lean#L912)), the divergent safepoints of `implicit-class`.

What the model did not say that §5 expected: the taint theorem for the ranked fixed point is empty, because under ranked rules no peek ever sees `absent`; the useful statement is the unranked one, and it holds for full taint but not for IntelliJ's rule as described, which is the new finding (I4), checked against `RecursionManager.java`: `prohibitResultCaching` marks only the frames after the re-entered one, and `afterComputation` restores the count to the re-entered frame's own stamp, so its `mayCacheNow` is true.

## 8. The namer as rules: where Track I meets Track L

Track L's theorems quantified over hand-written rule sets, one program's facts cut three ways. [`ScalaTypes/ToyNamer.lean`](../../scala-types/ScalaTypes/ToyNamer.lean) derives the rules from a program of the toy language: [`rulesOf cut p`](../../scala-types/ScalaTypes/ToyNamer.lean#L238) is the namer. The facts are a class's member names (`decls`, level 1, forwarders included), its parent (`info`), and each member's type (`mem`, level 2); the rule of a member's type walks its path through member lookups that ask `decls` and `info` of the classes on the way and `mem` of the members, with implicit classes as the fallback. A `Cut` says how a compiler bundles them: `fine`, every fact only what it says; `scalac`, no exports, a lookup finds a symbol without its info; `dotc`, a lookup forces the member's info, and an export reads the other class's member set *as indexed so far* when it is in progress (`TempClassInfo`) and skips a member whose type is in progress. Both of dotc's reads are peeks ([`Probe.peek`](../../query/Query/Lazy.lean)), so `forcePeek` and `forceT` run on the namer unchanged.

The language got one feature the Java toy lacks, Scala 3's `export`, because it is where the cuts differ, and Track L's two export findings become theorems by `decide`: L9 ([`l9_dotc_order_dependent`](../../scala-types/ScalaTypes/ToyNamer.lean#L338): `A`'s member set has `b` with `A.scala` typed first and not with `B.scala` first, the set without `b` memoized; [`l9_fine_order_free`](../../scala-types/ScalaTypes/ToyNamer.lean#L344)) and L2 ([`l2_dotc_order_dependent`](../../scala-types/ScalaTypes/ToyNamer.lean#L377): a conflict with `A.scala` first, both compile with `B.scala` first; [`l2_fine_cycle`](../../scala-types/ScalaTypes/ToyNamer.lean#L386): under the fine cut the two member sets are a true cycle, so agreement between the orders would need a fixed point of the name sets, not a lazier read). Full taint (§7) applied to the namer repairs L9's answer in both orders and stores nothing on the cycle ([`l9_taint_order_free`](../../scala-types/ScalaTypes/ToyNamer.lean#L354)): the price of taint on a cyclic program is the memo. The Java toy's own scenarios come out as the harness has them: the true cycle is a cycle under every cut, the implicit view resolves under every cut in either order, and the case class's synthetics are names the namer has ([`cycleToy_all_cuts`](../../scala-types/ScalaTypes/ToyNamer.lean#L401), [`implicitToy_order_free`](../../scala-types/ScalaTypes/ToyNamer.lean#L416), [`caseToy_names`](../../scala-types/ScalaTypes/ToyNamer.lean#L428)); what the harness finds beyond that is the kernel's state, which §4 and §7 model separately.

§9 takes the next step: the kernel over these rules.

## 9. The kernel as a model: `results.txt` is a theorem

[`ScalaTypes/ToyKernel.lean`](../../scala-types/ScalaTypes/ToyKernel.lean) is `Scala2Kernel.java` with `Global.java`, ported line for line where it matters, with every `force` of a member's type taken from the namer's rules (§8) through [`forceLog`](../../scala-types/ScalaTypes/ToyKernel.lean#L139), [`Query.Lazy.force`](../../query/Query/Lazy.lean#L55) with a log of the facts it completed, since each completion is a safepoint inside a completer. Everything else is kernel state ([`KSt`](../../scala-types/ScalaTypes/ToyKernel.lean#L124)): the synthetic methods a burst entered, the `SynthesizedMethods` attachments, the implicit factories' generations (a replaced symbol is a new generation; the fact records the view it went through, [`Typed.via`](../../scala-types/ScalaTypes/ToyNamer.lean), and the kernel checks the generation against the run's cache), the suspended warnings and the suppressions, the typed bodies, the target of a targeted check, and the scheduler. Exceptions run over the state (`ExceptT Exc (StateM KSt)`), so that a `TyperResult` keeps what the abandoned check did, which is the whole point. Requests nest through [`serve`](../../scala-types/ScalaTypes/ToyKernel.lean#L546) with a depth, and [`signalDone`](../../scala-types/ScalaTypes/ToyKernel.lean#L244) counts, injects the harness's event at safepoint `k`, finishes a targeted check at its target, and polls the queue when `interruptsEnabled` and not inside a completer. `Policy` is the Java one less the two bits the namer absorbs.

The harness is `Harness.java`: [`divergent policy sc`](../../scala-types/ScalaTypes/ToyKernel.lean#L601) counts the background's safepoints, takes the reference answers from the event sent afterwards, injects the event at each `k` and compares. Two theorems, checked by the kernel in about 25 seconds (`decide +kernel`): the safepoint trace of `case-class-completion` is the Java kernel's, name for name and in order ([`caseClassCompletion_trace`](../../scala-types/ScalaTypes/ToyKernel.lean#L765)); and for all seven scenarios the safepoint counts and the divergent sets under the policy before the PR, after it and the proposal are exactly those of [`results.txt`](../probes/interrupt/results.txt) ([`results_before_after_proposed`](../../scala-types/ScalaTypes/ToyKernel.lean#L774)). The port took one correction to agree: on a cyclic reference scalac gives every completer on the stack an error type as the error propagates up as a value, each ending with its safepoint, so the `cycle` scenario has 12 safepoints and not 11; `forceLog` returns the stack at the cycle for that. Holding the two kernels to each other over a space of scenarios (§10) then found three places where the *Java* toy was wrong about scalac, and both were corrected.

What this buys. A policy or a scenario is now predicted before the Java runs; a disagreement between the Lean and the Java kernel is a bug in one of them, the same relation the probes have to the real compilers; and the shape theorems of §7 can become lemmas about this kernel rather than about shapes read off it. What it does not yet cover: the dotc and PSI kernels (whose 0 divergences are by construction, [`nested_empty_stack_reorders`](../../query/Query/Interrupt.lean#L378)), `export` in the Java toy, and the fidelity gap of §4's implicit-class answer (the shadowed view is a kernel problem beside a fact that still holds the type).

## 10. A space of scenarios, and what it found

The Lean kernel runs a scenario in milliseconds, so [`ScalaTypes/ToySpace.lean`](../../scala-types/ScalaTypes/ToySpace.lean) runs the harness over a space ([`space`](../../scala-types/ScalaTypes/ToySpace.lean#L44)): every program of `Int` and two or three declarations from a menu of eight (a case class with and without a companion of its own, an implicit class, two consumers through paths, a second case class reading the first, a deprecated member with and without a `nowarn` consumer), in every order, with a completion at each inferred member and a whole-unit request: 1,372 scenarios over 392 programs, under each policy.

**It debugged the toy first.** The first run reported divergences under the proposal for programs with the implicit class or the case class declared *after* its consumer. Reading scalac for them: the implicit factory is entered by the namer (`enterClassDef` → `enterImplicitWrapper`), `copy` is the namer's synthetic too (`addCopyMethod`, through `unit.synthetics` like `apply` and `unapply`), and a replaced factory's tree is never found by `addSynthetics`, which walks the scope. The Java toy had all three as the typer's, and so did the port. Both were corrected (the burst is now `equals`, `hashCode`, `toString`), `results.txt` regenerated, and the theorem of §9 restated; the numbers of §4 moved by one safepoint in two scenarios.

**What remains, after the correction.** Before the PR, 755 scenarios diverge; after it, 369, of which 312 are whole-unit requests (the I1 family, every program with a case class) and 57 are completions; under the proposal, the same 57 completions and nothing else. Every one of the 57 has the case class declared after the member whose completion is asked, and diverges at exactly the safepoints before the class's burst ([`consumerFirst_proposed_before_burst`](../../scala-types/ScalaTypes/ToySpace.lean#L88): twelve of twenty): a targeted check types the unit up to its target and never reaches the class, so the completion lists it as the namer left it, without the typer's overrides of `equals`, `hashCode` and `toString`, while the reference, after the background, has them. In scalac those names are inherited from `Any` and `Product` anyway, so the gap shows as the inherited signatures in place of the case class's (`dollar-completion`'s check file lists the latter), not as missing names. That is the targeting gap of §6, and no policy on synthetics closes it (finding I5).

**Both predictions held.** I1 was confirmed on the PR's head on 21 October (`full-check-interleaved`). I2 the next day with `full-check-late`: the same test with the whole-unit request served at the `signalDone` of `Use.local`'s `DefDef`, after the background has typed the local case class; the request's own tree has `class L` with no synthetic member at all, and the typed right-hand side of `local` is a fresh tree. The mechanism is a second consumed map: `typer.transformed`, the right-hand sides typed by completers to infer a type, is read by `lookupTransformed` with `remove`, so whichever check reaches `typedDefDef(local)` first takes the typed body and the other retypes it from scratch and finds `L` "already has" its synthetics. The projected patch ([retronym/jvm-lang-models#12](https://github.com/retronym/jvm-lang-models/issues/12)) makes both trees whole, and passes the presentation suite (51), the typer and interactive junit tests (19), and 26 case-class and default-getter tests under `-Ycheck:typer`.

## 11. Abort and restart, on the kernel

The kernel of §9 has a second way to serve a request ([`Mode`](../../scala-types/ScalaTypes/ToyKernel.lean#L99)): instead of being serviced inside the background check at a safepoint, the request *aborts* it (`Cancelled` unwinds to the run loop), runs on an empty stack, and the background restarts. Three cleanup bits, each an obligation of the design discussed for Scala 3 ([track-i-scala3-cancellation.md](track-i-scala3-cancellation.md)): `restore` puts the unit-scope state back as the background found it (the top-level `catch`: [`takeSnapshot`](../../scala-types/ScalaTypes/ToyKernel.lean#L596), [`restoreSnapshot`](../../scala-types/ScalaTypes/ToyKernel.lean#L601)); `keepDiagnostics` exempts what the completers reported from that restore; `perCheck` gives every check its own copy of the namer's unit-scope state. The same seven scenarios, every safepoint, `decide +kernel`:

| mode | before | after | proposed | theorem |
|---|---|---|---|---|
| abort, no cleanup | diverges widely | `case-class-*` at 3..15, `targeted-consumes` at 4..17: the burst, once begun, is skipped on restart ("already has"), and the consumed trees are gone | **0 everywhere** | [`abort_proposed_safe`](../../scala-types/ScalaTypes/ToyKernel.lean#L737), [`abort_after_not_resumable`](../../scala-types/ScalaTypes/ToyKernel.lean#L743) |
| abort + restore | | `nowarn` at 6..13; `cycle` at 1..11 under every policy: the warning `Use.foo` and the cyclic-reference errors were emitted when their facts completed, the restore wipes them, and the memoized facts never re-emit them | same | [`abort_restore_loses_diagnostics`](../../scala-types/ScalaTypes/ToyKernel.lean#L751) |
| abort + restore + diagnostics kept with the facts | | **0 everywhere** | **0 everywhere** | [`abort_restore_keep_safe`](../../scala-types/ScalaTypes/ToyKernel.lean#L759) |

Three things follow. Idempotent synthetics alone make abort safe: a check that regenerates what its tree lacks has nothing to restore. Without that, the two consumed maps and the burst are the frames that are not resumable, which names the `finally`s scalac would need. And diagnostics are a consumed side effect of fact completion: a restart that keeps the facts must keep what they reported, or report from the facts rather than from the check (dotc, which drops the file's facts with the run, regenerates them; a scalac-shaped kernel does not). [`abort_proposed_safe`](../../scala-types/ScalaTypes/ToyKernel.lean#L737) is also the first theorem in this track with a hypothesis over all seven scenarios and no divergent safepoint at all.

## 12. Trees

§6 said targeting and incrementality are about trees, and §11's session (track-i-scala3-cancellation.md §5; as built, with the typer skipping every sibling off the path to the target and the x-ray that shows it, [track-i-dotc-session-design.md](track-i-dotc-session-design.md)) reuses within a run but not across an edit. [`ScalaTypes/ToyTree.lean`](../../scala-types/ScalaTypes/ToyTree.lean) and [`Query/Revision.lean`](../../query/Query/Revision.lean) (22 October 2026) are the smallest tree that carries both, over the namer of §8; no `typeUnit`, no consumed map, no expressions.

**The green tree.** A unit is a list of declaration nodes, each with its member nodes, every node with an id ([`Tree`](../../scala-types/ScalaTypes/ToyTree.lean#L54)). An [`Edit`](../../scala-types/ScalaTypes/ToyTree.lean#L84) replaces, inserts or deletes a declaration, or replaces one member; the replaced or inserted nodes get fresh ids and every other node keeps its own ([`Tree.apply`](../../scala-types/ScalaTypes/ToyTree.lean#L98)), which is Wagner and Graham's reuse without the parsing, and Roslyn's green tree without the red one, since positions here are paths (declaration index, member index), not offsets. Node identity is what lets a typed form survive an edit elsewhere in the file: in [`tier3a_scope_insert`](../../scala-types/ScalaTypes/ToyTree.lean#L497) a declaration inserted at index 1 moves `Use` to index 2, and `Use`'s typed forms, keyed by id, are reused.

**The typed tree as facts.** Two facts per node, keyed by id, whose rules ask the namer's facts ([`ToyTree.rulesOf`](../../scala-types/ScalaTypes/ToyTree.lean#L169)): `typedMember` is the member's type and, when the type is declared and there is a body, the body typed against it (the typer's work on a `DefDef` with a result type); `typedDecl` is the declaration's body list with synthetics, each with its type, as [`unitAnswer`](../../scala-types/ScalaTypes/ToyKernel.lean#L348) prints it, with a case class's synthetic companion. The namer's rules are lifted unchanged through [`Task.rename`](../../query/Query/Interp.lean#L59). The unit's typed tree is the store restricted to these facts, filled on demand; there is no loop over the statements, so nothing to unwind from and no trees for two checks to share, which is what made §4's attachments necessary. What the model loses by this: scalac gives a completer on a cycle an error type and types the rest of the class, while here the fact black-holes, so a declaration with a true cycle has no typed form at all (`cycle`'s `C`); its well-founded members still have theirs.

**Four theorems.**

| claim | theorem | by |
|---|---|---|
| Targeting is demand: a request at a path forces the typed fact at that node and what it asks, nothing else, and answers as the whole-tree check does | [`targeted_eq_whole`](../../scala-types/ScalaTypes/ToyTree.lean#L362): on the seven scenarios, under the fine and scalac cuts, at every path, from an empty store and from the whole check's store the same `Out`, and the targeted store within the whole one; [`targeted_work_caseToy`](../../scala-types/ScalaTypes/ToyTree.lean#L369): the completion at `Use.f` runs 6 rules of the unit's 20 | `decide` |
| The session is a fresh run, request for request | [`Query.Revision.session_eq_fresh`](../../query/Query/Revision.lean#L331) for ranked rules ([`forceAll_ok`](../../query/Query/Lazy.lean#L160) over `reval`); [`session_eq_fresh_toy`](../../scala-types/ScalaTypes/ToyTree.lean#L442) on the scenarios, every path in order and in reverse, `cycle` included, which the ranked theorem does not cover | induction; `decide` |
| Re-validation by trace is sound | [`Query.Revision.reuse_sound`](../../query/Query/Revision.lean#L235): from a store of revision `r` agreeing with `r`'s fixed point, with `r + 1`'s rules ranked and the edit's footprint semantic (`Same`), re-validating any fact returns `r + 1`'s value and leaves a store agreeing with `r + 1`'s fixed point, recorded traces included | induction on fuel, as [`force_ok`](../../query/Query/Lazy.lean#L111) |
| The three tiers of invalidation | [`tier1_body_edit`](../../scala-types/ScalaTypes/ToyTree.lean#L461), [`tier2_signature_edit`](../../scala-types/ScalaTypes/ToyTree.lean#L478), [`tier3a_scope_insert`](../../scala-types/ScalaTypes/ToyTree.lean#L497), [`tier3b_scope_member`](../../scala-types/ScalaTypes/ToyTree.lean#L520) | `decide` |

The equality in the first row holds at every path because nothing a typed form reads here is typer-only state: the synthetics are the namer's (§8). The I5 shape, a completion served before the class is typed that sees the namer's members and not the typer's overrides, needs a member that exists only once the typer has run, and this model has none; where a compiler has such members (scalac's `addSyntheticMethods`), the row fails exactly at the paths whose typed form reads them, and the repair is the one I5 names, to make them the namer's.

**Revisions.** [`reval`](../../query/Query/Revision.lean#L118) is `force` with one more branch: a fact of the previous revision whose rule the edit left alone is reused if its recorded deps, re-validated first and in the order the rule asked them, still have their old values; otherwise its rule runs. In order matters: a dep after a changed one may not be asked at all under the new oracle, and [`mem_trace_of_agree_prefix`](../../query/Query/Revision.lean#L32) is the lemma that each dep checked is one the rule still asks. A recomputed value equal to the old one keeps the old revision's `since`, so backdating is comparing values rather than revisions (Salsa's `changed_at`). `Same` is a hypothesis of [`reuse_sound`](../../query/Query/Revision.lean#L235), not a theorem about [`rulesOf`](../../scala-types/ScalaTypes/ToyNamer.lean#L274): how a compiler knows which rules an edit left alone is its own business, and the toy's answer is a [`footprint`](../../scala-types/ScalaTypes/ToyTree.lean#L293) per edit (the node's own facts; the member types that read the edited name other than through a fact, as a declared type or the first step of a path; every path when an implicit class comes or goes; a change of deprecation, which `step` reads directly, touches every member type). Each tier theorem therefore also checks the re-validated store against a fresh run of the new revision and `Same` on every fact outside the footprint, by `decide`; the footprint is the model's claim, validated per example. That the footprint is by *name* is not an accident: the namer's direct reads of the program (is this a top-level object, is this an implicit class, is this member deprecated) are the reads that are not facts, and the name they read is what Zinc hashes.

The tiers, on an example each. (1) An edit inside a body whose type is declared changes only the new node's typed form; the member's type and its owner's member set are in the footprint and rerun, come out equal and are backdated, and everything downstream (`p = q.c`, `s = q`, the declaration's typed form) is reused by trace without running: 3 rules of 14. (2) A declared type changes exactly the facts whose traces hold it, `q.c`, `q`, their typed forms and `C`'s, and not `c` or the unrelated class `D`. (3a) A declaration added to the unit's scope reruns the lookup of its name that had failed (`Use.r = X.x` was "not found: value X") and nothing else of `Use`. (3b) A member added to a parent class reruns every lookup whose trace holds the parent's member set: the one that found `a` there (backdated) and the one that failed there (`k = n`, now typed), while `l = j`, satisfied in the subclass's own set, is reused. The failed lookup is in the trace because [`lookupIn`](../../scala-types/ScalaTypes/ToyNamer.lean#L159) asks `decls` of each class it tries, which is the whole content of "failed lookups must be recorded" (T1's coverage, [theorems.md](../../../docs/theorems.md)).

**The session on `big-file`** ([`big_session`](../../scala-types/ScalaTypes/ToyTree.lean#L613), `decide +kernel`): the editing session of `results-sessions.txt`, a completion near the top, three edits at the end each followed by it, a completion at the end, the whole unit. Every answer is the fresh store's. The completion at the top runs 4 rules; each edit after the first runs the 3 of its footprint and re-validates the other 280 facts by trace, and the requests after it run nothing, against 242 for each whole-unit request on a fresh store. The first edit runs 279: [`Rev.edit`](../../scala-types/ScalaTypes/ToyTree.lean#L313) re-validates every fact of the unit eagerly, and after one targeted request most have never been computed, so the first edit pays for the unit, once. Re-validating on demand across several revisions, so that it costs 3 as well, needs an entry to remember the revision of its *rule* and not only of its value, so that a fact skipped at revision `r + 1` can still be checked at `r + 2` against the footprints of both edits; [`reuse_sound`](../../query/Query/Revision.lean#L235) is stated for one step, with the old store agreeing with one fixed point, and that generalization is future work.

**The Java twin** ([`Revisions.java`](../probes/interrupt/src/pctoy/Revisions.java), the `dotc-revisions` kernel; `run.sh --sessions` and `--tiers`, [`results-sessions.txt`](../probes/interrupt/results-sessions.txt), [`results-tiers.txt`](../probes/interrupt/results-tiers.txt)). The same design in the toy, held to the Lean model: edits bump a revision, symbols are re-entered by name path, every fact records its trace with lookups (failed ones too) as pseudo-facts, re-validation is on demand in trace order with backdating, diagnostics are stored on the fact that produced them. Every answer equals the fresh-run kernel's; on `big-file` the three edits cost 0 rules each against the session's 6 and the fresh kernel's 202, and the whole unit afterwards 6 (the appended classes). The two models disagree in five places, each a modelling choice rather than a bug: the Java's declaration input is the header and member names, so a body edit does not rerun the owner's member set (2 rules of 12 against Lean's 3 of 14, and nothing changes); the Java keys typed forms by name path, so an unchanged typed form backdates where Lean's fresh node id makes it new; the Java invalidates failed lookups through a top-level scope input and Lean through the name's own fact; a cycle met during re-validation recomputes in the Java and returns `.cyc` in Lean; and the Java verifies across several revisions at once (`verifiedAt` per fact), which Lean lists as future work. The tier checks pass on all three scenarios: a fact is recomputed iff its old trace holds a fact that changed since it was verified.

**What this says for dotc.** Three things, each a line of track-i-scala3-cancellation.md §5 made concrete. A completer must be a function of its node and owner, the shape of [`ToyTree.rulesOf`](../../scala-types/ScalaTypes/ToyTree.lean#L169) (`typedMember id` reads the node and asks facts), not a closure over a `Context`, because a reused fact is run under a later revision's oracle and its recorded deps are all it may depend on; `Namer.Completer` capturing `ctx` is the obstacle, and `cleanup`, which turns every still-lazy symbol of a typed tree into `UnspecifiedErrorType` so that no completer outlives its run, is the symptom of it: with completers as functions of node and owner there is nothing to clean up, and a targeted run can leave the members after the target lazy. `stillValid`/`bringForward` for stale denotations in `Mode.Interactive` is `reval`'s reuse branch with the dep check missing: `bringForward` keeps a denotation whose symbol still exists in the new run, which is the footprint by node identity without the trace; what the model adds is the check of the recorded deps in order, and backdating. And the footprint is by name where the namer reads the program directly, which in dotc is every `Context`-based lookup (`typedIdent` through the scope chain, implicit scopes), so a tree model for dotc needs those lookups to go through facts that record misses, as `lookupIn` does, or a name-level footprint as Zinc's.

## 13. What the dotc session taught the model

The session of [track-i-dotc-session-design.md](track-i-dotc-session-design.md) is §12's targeting and §11's abort built into dotc ([`dotc-session.patch`](../../../docs/upstream/dotc-session.patch), staged as [retronym/scala3#68](https://github.com/retronym/scala3/pull/68)), and the x-ray drove the real spike three ways: with Metals' own presentation-compiler suites (completion, hover, definition, signature help, all through `runUpTo`), with two suites of its own (`CompletionSoakSuite`, a random walk of requests, cancellations and edits; `SessionOracleSuite`, a hover at every identifier of four of the compiler's sources against a fresh whole-file run), and with an editor (Metals 1.6.9 in VS Code on the compiler's own 478 sources). It found I12–I28 ([findings.md](../../../docs/findings.md)). The design note's §9 sorts them, after re-running the candidates on an unmodified checkout. Five are bugs of the stock compiler and Metals today, whatever is built on them: I7 as corrected (a Namer completer refuses a later run, which on stock is reached only when an abort unwinds the run that entered the file), I10 (the 16-bit run id of a long-lived driver overflows into the phase bits), I11 (nothing polls for cancellation inside implicit search), I12 (most of a completion's 115–176 ms is spent outside the compiler) and I15 (an empty prefix bypasses the caching driver). The rest are *design constraints* of any targeted or resumable typer, which a whole-file run per request never meets: I8, I13, I14, I17, I19, I20–I23, I25 and I26, with I28 as the third instance of I21's and I25's rule; I24 and I27 have mechanisms in [notes-i24-i27-analysis.md](notes-i24-i27-analysis.md) and belong with them, and I18 is open. That is the projection-back rung of [method.md](../../../docs/method.md) §1.8 doing what it is for: the toy has no runs with identity, no attachments, no desugaring and no providers, so none of the second list could have come from it, and each says what the model left out.

**The lesson, in the model's terms.** The toy and the Lean model assume every answer-relevant fact is a *fact*: a rule, forced on demand, whose value is a function of what it asks ([`ToyTree.rulesOf`](../../scala-types/ScalaTypes/ToyTree.lean#L169)); a request at a path forces what that path needs and nothing else, and [`targeted_eq_whole`](../../scala-types/ScalaTypes/ToyTree.lean#L362) holds at every path. The real typer has two more kinds. It produces facts as *side effects of typing a sibling*: a sealed trait's `children` registered by the completers of enum cases elsewhere in the file, and a clashing synthetic `apply` marked absent only by its own completer (I13); the members of a refinement's synthetic class, which exist only once its template is typed (I25); the definition a provider reads, which is a `DefTree` with that symbol in the typed tree, not the symbol (I26). And it *consumes trees*: typing takes an untyped tree's attachments, so it cannot be typed twice (I8), and desugaring merges one tree's products into another's, a case class's `apply` and `unapply` into its companion object's tree, which a replaced tree loses (I22). Targeting is sound exactly for the first kind; §12 said where it fails, at the I5 shape of a member that exists only once the typer has run, and I13 and I25 are that shape in dotc. The other two kinds need one of three repairs, each of which the spike used: a rule over the whole list (scalac's `typedStats` types the following definition for a scaladoc template, and the spike's "a tree that outlives the request as a value is typed whole", I21, I25, I28, is the same move one level down); forcing on answer (`completeSymbolsOf` before a file is left, I17; `typeDefinitionOf` before a provider reads a definition, I26; a whole-file `run` that completes the session); or making the facts rules (the completers made sufficient for `children`, I13; the model's namer derives the companion's synthetics from the class, [`replace_keeps_merged`](../../scala-types/ScalaTypes/ToyTree.lean#L548)). This is the dividing line the model draws between `rulesOf` and kernel state (§8, §9), and the spike confirmed it: every design constraint it found sits on the kernel side.

**Where each lesson lives now.**

I14 and I19 are about dotc's representations, a run-indexed period and a span that is an offset in one source; the model's revision is a number and its positions are paths, so it cannot have them, and each is a rule for the real system rather than for the model (the clock does not roll back; a span is compared only within its source).

**What the session told the design.** The editor's expensive questions are ranges, not points: semantic tokens, inlay hints and folding over the visible lines, and document highlight, a whole-file run on every cursor move (136 of 142 whole-file runs in one session), so once a hover is served in 20 ms the next targeting is by range ([track-i-dotc-session-design.md](track-i-dotc-session-design.md) §11). An edit inside a body should keep the run, which is IntelliJ's block modification count and §12's first tier ([`tier1_body_edit`](../../scala-types/ScalaTypes/ToyTree.lean#L461)) brought to dotc: re-type the definition alone, in its recorded context, when its signature tree is unchanged. And Metals restarts the presentation compiler after every build compile, which discards a session still valid for the file being edited.
