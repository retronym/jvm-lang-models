# Member types in IntelliJ Scala: is the substitutor chain an `asSeenFrom`?

**Context.** PR [retronym/intellij-scala#5](https://github.com/retronym/intellij-scala/pull/5) removes the false errors IntelliJ reports on scala/scala's own cake-pattern sources by aligning its type operations with scalac's. The remaining failures (`Importers.scala`, `MatchWarnings.scala`, refinement members, sibling-trait spellings) share a cause: the type of a selected member is computed differently. scalac applies **one** map, `info(m).asSeenFrom(pre, owner(m))`. IntelliJ applies a **chain** of substitutor links, `sig_C(m) >> ThisTypeSubstitution(fromType, anchor) >> …`, each link an anchored owner-chain walk, with the resolution route deciding which links and anchors. This note asks whether the chain can agree with scalac in principle, and if so, which properties of a chain guarantee it.

**Method.** The two procedures were modelled in Lean 4 (this directory, ~430 lines, no Mathlib). A class is its owner path; a type has this-leaves, paths and type variables; the environment is abstract: `bpre p c` = `(p baseType c).prefix` and `hasBase p c`. scalac's `thisTypeAsSeen` is structural recursion on the owner path, so termination is the checker's. The one assumption is **lockstep**: `asSeenFrom` commutes with `bpre`/`hasBase`, which scalac satisfies by construction and which, for IntelliJ's `BaseTypes`, is the contract the TCK's baseType dimension checks.

**Results.**

1. *Composition.* `A(p₂,c₂) ∘ A(p₁,c₁) = A(A(p₂,c₂)(p₁), c₁)` whenever the first map rewrites every this-leaf of its input (`compose`). By induction, any chain of anchored walks is one `asSeenFrom` from a composed prefix (`chain_is_single`). So the chain architecture is sound in principle, and inherits termination from the walks.
2. *The anchor chooses the prefix, not the soundness.* `compose` holds for any `c₂`. A mis-anchored link does not make the chain "not an asSeenFrom"; it makes it an `asSeenFrom` from the wrong prefix. For `MatchWarnings` (case b) the chain anchored at the declaring owner is `typer` seen from `MatchTranslator.this`; anchored at the class whose view the type is in, it is `typer` seen from `TreeMakerWarnings.this`, which is scalac's answer (`Cases.B`, by computation).
3. *Where IntelliJ's walk differs.* With the narrow-against-target fallback modelled, IntelliJ's walk equals scalac's wherever the fallback does not fire (`IntelliJ.agrees`). For `Importers` (case a) the fallback rewrites `Importers.this` to `from` where scalac's walk runs out of prefix and stops (`Cases.A`). This reclassifies that route from "wrong anchor" to "unfaithful walk".
4. *Three structural constraints with named theorems.* **C1** each link is anchored at the class of the running composed prefix ⇒ the chain views from the intended prefix (`chain_is_intended`). **C2** a link does not rewrite its own target ⇒ it is idempotent and duplicates can be dropped (`idempotent_of_fixed`, `dedup`). **C3** a substitutor threaded into resolve state has no this-links ⇒ it never re-anchors (`stateSafe_preserves_this`).

**Assessment.** The chain is a staged `asSeenFrom`, and every cake-specific allowance on the branch (self-type reach, `targetDenotesLeafClass`, the inherits-the-cursor exit, no self-embedding) compensates for a violation of C1–C3 somewhere upstream. The case that the chain cannot fix by itself is the sibling-trait spelling (`Symbols.this.Symbol` for scalac's `Definitions.this.Symbol`): resolution hands the chain the wrong starting prefix. The fix there is the SCL-7008 rule generalized, `A(C.this, S)(sig_S(m))` for a member reached through `C`'s self type `S`. Not proved: lockstep for `BaseTypes.baseType`, and termination of the fused engine with outputs re-entering resolution; `chain_is_single` says that under C1–C3 no output needs re-rewriting, which is what makes the brake redundant.

## Assertions for `ScSubstitutor`

All behind one registry flag (the `TypeRecursionGuard` one), on in tests, off in production until silent on the broad set. "This-link" = `ThisTypeSubstitution`; `cls(t)` = `t.widen.extractClass`; `chain(c)` = `c`, `c.containingClass`, …

| | Where | Check | Cost | Theorem |
|---|---|---|---|---|
| **A1** fixed target (C2) | `ScSubstitutor.apply(target, seenFromClass)` | the spine root this-type of `target` (via `spineRootThis`) names no class on `chain(seenFromClass)` | O(nesting), keep on | `idempotent_of_fixed` |
| **A2** state-safe (C3) | `ScalaResolveState.withMatchClauseSubstitutor`, and any `withSubstitutor` whose value is threaded to other references | `subst.substitutions` contains no this-link; better, make `matchClauseSubstitutor` a `TypeParamSubstitution`-only type | free | `stateSafe_preserves_this` |
| **A3** adjacent anchors, cheap C1 | `ScSubstitutor.followed`, for each pair of nearest this-links `(t₁,a₁) … (t₂,a₂)` | `a₂ == cls(t₁)` when `t₁` is a `ScThisType` (the `sig_C >> fromType` shape, where the running prefix is `t₁` itself) | one `extractClass` per pair | `chain_is_intended` (exact when the previous link rewrote the running prefix to its target) |
| **A4** running anchor, exact C1 | `followed`, test flag only | fold the this-links: `run := t₁`; for each later `(t,a)`: assert `a == cls(run)`, then `run := ThisTypeSubstitution(t, a)(run)` | one `baseType` walk per link | `chain_is_intended` |
| **A5** no leftover (precondition of `compose`) | `ThisTypeSubstitution.subst`, after a firing on `D.this` is *refused* by `ownerChainMatches` | `D` is not on `chain(seenFromClass)`; a refusal where it is means an upstream link was mis-anchored | per refusal only | `inView` hypothesis of `compose` |
| **A6** anchored | `ScSubstitutor.apply(target, null)` | log, then fail: the anchorless walk is scalac's unmatched case, not an inheritance narrow (refinement members need a synthesized anchor first) | free | `IntelliJ.agrees` applies only to anchored walks |

A1 and A2 are free and can stay on. A3 is the one that would have listed every site needing the I1 fix (every `substitutorWithThisType(declarationAnchor(m))` after a signature substitutor), so run it first on the broad set and treat its failures as the worklist. A4 and A5 are diagnostics. A6 is the exit from the anchorless mode. Each should get a TCK `termType` row for the case it guards (a: `Importers`, b: `MatchWarnings`, c: `Utils.reifier`, d: `Definitions`/`Symbols`), since the assertions check chain shape and only the TCK checks lockstep.
