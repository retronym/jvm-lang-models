# A whole-unit request served inside the background check loses the unit's synthetics ([scala/scala#11328](https://github.com/scala/scala/pull/11328))

**Venue.** A comment on [scala/scala#11328](https://github.com/scala/scala/pull/11328), with the test and the patch. Posted first as a comment on [retronym/jvm-lang-models#12](https://github.com/retronym/jvm-lang-models/pull/12#issuecomment-6316524603).

**Finding I1, confirmed on the PR's head (`c388b9113b`).** `askType(source)` served at a `signalDone` inside the background type check of the same unit (before its case class is typed) types the unit nested, adding the companion, `apply`/`unapply` and the synthetic methods to its own tree and consuming `unit.synthetics`. The background check then resumes on the old tree: `addSyntheticMethods` finds `L` "already has" the methods and returns the template unchanged, `addSynthetics` finds nothing left, and `typeCheck` assigns `unit.body` last, so the tree later `askLoadedTyped`s return has `class L` with no synthetic methods and no `object L` statement at all. The PR's `uninterruptible(addSynthetics)` only moves the request past that window.

**Test.** `test/files/presentation/full-check-interleaved`: the PR's `local-case-class-interleaved` with `askType(src, forceReload = false)` instead of the completion, a wait for the background compile (`while (compiler.isOutOfDate) Thread.sleep(10)`, without which `askLoadedTyped` returns the nested tree and hides the bug), then `askLoadedTyped`; it prints the synthetic members of `L` and its companion in both trees. At the PR head: `final class L: ` and no `final object L` line.

**Fix.** [`scalac-idempotent-synthetics.patch`](scalac-idempotent-synthetics.patch) (8 files, against `c388b9113b`): the two shared resources are made idempotent instead of excluded. `ClassMethodSynthesis.createInternal` finds the synthetic method the class already has (name, matching type, `isSynthetic`, owner) and regenerates the tree for it; `addSyntheticMethods` keeps only the phase check and skips a method only when the template already carries its tree; `Typers.addSynthetics` consumes nothing, skips a synthetic whose tree the statements already hold, and stores the typed tree back. Removed: both `uninterruptible` wrappers and `Global.uninterruptible`, `consumeSynthetic`, the `InteractiveTyper` overrides and `SynthesizedMethods`, and the now-unused symbol lists. Kept: the companion re-entry in `enterExistingSym`, the implicit factory, the suspended warnings, `interruptsEnabled`. `compiler/compile` and `interactive/compile` clean; `partest` on `dollar-completion`, `t12308`, `implicit-class-interleaved`, `local-case-class-interleaved`, `doc` and the new test: 6/6. Not run: the full presentation and junit suites, `-Ycheck:typer` (TreeCheckers retypes typed trees and relied on consumption; the guards are meant to cover it).

The toy that predicted it: [`track-i.md`](../../packages/scala/docs/track-i.md) §4, `scalac-after` versus `scalac-proposed` on `case-class-loaded`.
